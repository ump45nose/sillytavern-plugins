# M5：服务端采集收口

2026-10-12 开始、2026-10-13 更新：完成现有阅读类型的一轮服务端核对，修复检索查询与历史回填调度。正文搜索性能与 CRM 全量同步耗时仍需收口，当前不将 M5 标为全部完成。微信模型提炼已经暂停，不参与当前收口；Mac 实际阅读体验独立登记，不作为服务端前置条件。

## 本轮实际修复

真实长电脑活动正文的分页读取正常，但正文检索超时。原查询逐对象执行正文匹配，正式库约有 72 万个正文块，只存在对象/顺序主键索引。

本次在已有 PostgreSQL 中安装 `pg_trgm`，并发补建 `ix_hub_content_search_trgm` 和按阅读列表排序的 `ix_hub_content_reading_order`。全局长词匹配先取得去重的对象集合，并明确物化，避免数据库在外层列表中重复执行；短词按对象主键读取正文。列表选定对象后，整页一起取得首个命中摘录，替代每个结果重复查询正文两次。头与摘录使用同一快照，保持原筛选、字面包含匹配和版本规则。

索引构建与镜像切换分开，已有大库不会在采集写入锁内补建大型索引；新空库由加工迁移初始化。本次大型索引构建仅在操作连接上使用 `maintenance_work_mem=512MB`，搜索事务单独使用 `work_mem=64MB`，均未修改 PostgreSQL 全局设置。两个正式索引均已确认有效。加工 schema 仍为 3，未改原件或来源水位，也没有新增检索服务。

还发现启动回填会完整扫描全库，超过 900 秒后重试却丢失位置；回填结束前不会处理新数据的阅读队列。改为每批 50 条，在入队的同一事务中保存内部检查点 `processing:reading-backfill`，批次之间穿插现有阅读队列。服务重启继续上次位置，规则版本变化才从头核对；手工定向 rebuild 保留原用法。内部检查点复用现有 `hub_checkpoints`，不占用各数据源的采集水位。

索引与查询方案参考 [PostgreSQL 官方文档](https://www.postgresql.org/docs/17/pgtrgm.html)。短于三个字符的查询可能无法利用有效的 trigram 过滤，仍保留原字面搜索语义；不以长词验证代替所有短词的性能承诺。

## 验证范围

只做最后一轮适用路径核对，不运行全库测试套件，不在正式库新增测试来源或测试账单。真实个人正文和令牌不写入仓库，临时脚本只输出类型、数量和结论。

隔离 PostgreSQL 已通过更新、删除和旧任务不能回写的检查。新查询和新空库索引初始化也通过了该链路的针对性复查。健康规则检查了累计值不相加、重叠睡眠不重复计时、缺失与零；财务规则检查了 Decimal、多币种、待确认与未知类型。

Emby 使用两条模拟观察点检查了日归组、暂停字段、逐条引用和观看时长保持未知。正式来源当前没有个人播放会话，因此真实播放采样及播放器行为尚未验收；空检查成功不代表播放路径已验收。

真实归档共核对 31 种现有阅读 variant，每类选一份就绪对象：详情、全部正文分页及全部依据与已存加工结果一致，依据哈希均对应当前原件，正文响应在 256 KiB 内。长电脑活动另有一份 1,298 块样本读取完成；不等于全库每条内容已逐条验收。文档类同时核对正文与原件，NUL 只在阅读副本中作一对一替换。鉴权拒绝与微信提炼 disabled 状态通过。

新增回填修复在隔离 PostgreSQL 中核对：分批后换 Repository 实例仍继续原位置，批次之间可以发布新阅读对象，完成后不重复扫描，原 Memos 采集水位保持。

搜索核对实际发现超时，不能写成全部通过。0.4.6 的真实活动摘要搜索超过 60 秒；之后的候选查询在当前负载下仍出现 15–40 秒超时。0.4.7 发布后复查 Memos 短词、真实活动摘要关键词和全局短词，三项均触及检查连接的 20 秒执行限时；检查只读并自动取消自身查询。索引有效和物化查询并未解决当前实际搜索性能，不得据此宣布通过。

正式采集还观察到 CRM 全量读取约 2.6 万条原生交流记录，逐批更新重复记录的新鲜度，持有来源锁期间实时 CRM 写入持续等待；一轮达到既有 900 秒限时后重试。进程栈与持续变化的数据库语句确认它仍在推进，不是已证明的重复获锁死锁。后续先处理 CRM 全量核对成本及写入等待，并继续收口正文搜索；不新增未经证明的锁补丁。

## 实际边界

- Memos 日报读取确认后的终稿；Hermes 读取已有产物。终稿不等于逐字聊天原话，本轮没有新增主观状态问卷。
- Git 覆盖既有提交和本人创建的 PR，不包含所有本地分支、评审及 Issue。
- Navidrome 记录是源库保留的客户端上报，不代表测量到的听歌时长。
- Emby 只有接入后的当前会话采样，不回造历史或精确观看时长。
- 微信完整归组和原文阅读继续运行；提炼的执行、新任务生成、积压统计都已暂停，旧结果保留供后续分析设计参考。
- Mac 真机正文、播放和控件体验另行验收；当前没有客户端阻塞项。手机采集仍在分析完成之后。
