# 收窄后的服务端边界

当前目标：补齐微信和 Skysight 的跨设备同步、健康与账单的长期持久化、网络流量的采集存储，以及 Plaud 的自有转录材料。来源清理先行，六类数据的详细结构随后确定。

## 来源职责

| 来源 | 保留职责 | 待设计内容 |
| --- | --- | --- |
| CRM/微信 | 按联系人/群聊归档消息和附件 | 精简人物画像、互动摘要及重复载荷 |
| Skysight | 同步原始片段与已有摘要文件 | 文件归档与定位索引，减少 AX 大文本副本 |
| Health | 保存手机上传样本 | 样本身份、区间、单位和跨上传包去重 |
| AutoAccounting | 保存可更新的源账单 | 金额、币种、账户、分类和删除语义 |
| 网络流量 | 采集和保存时间桶累计值及缺口 | 必要维度和测量位置边界 |
| Plaud | 同步音频并输出自有转录 Markdown | 原话、说话人、时间定位和转录质量 |

Memos、GitHub、Emby、Navidrome、Google Calendar/Tasks、Token Monitor 和邮件继续使用各自系统的存储与接口。Mem0 和 Hermes 报告不作为采集来源。

本轮只移除范围外的链路，不执行数据模型迁移、不物理删除旧镜像。共用稳定身份、同步确认、附件和只读访问，避免为了统一而重复保存各来源整份内容。分析模块及新 MCP/事件产品能力之后单独设计。

实施进度见 [来源清理计划](plans/2026-10-15-source-cleanup.md)。
