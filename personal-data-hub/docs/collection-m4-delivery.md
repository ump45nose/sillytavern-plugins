# M4：接入流程、Git 与 NAS 活动

2026-10-12，服务端实施记录。功能测试按用户要求留到采集侧开发完成后统一做；本阶段只核对实际来源和受影响服务的上线状态，不修改 Mac 客户端。

## 实现结果

[数据源接入流程](source-onboarding.md)已经按 M1–M3 的真实扩展点整理：范围与身份 → Record/Batch → 阅读加工 → 内部读取和控件需求 → 上线与历史补采 → 最后一轮简单验收。模板改为实施版；新增来源依旧使用现有调度、库、附件和读取鉴权，不新增协议平台或业务 MCP。

Git 保留既有鉴权、出站代理与 repo+sha 身份。采集窗口有固定上界，完成后推进水位，保留 72 小时回看和每周最近 30 天对账；超过搜索上限就拆时间范围。新增本人创建的 PR 当前状态与完整描述，实际 merged/closed 时间来自 PR 详情；评审、Issue、其他参与的 PR 及所有本地分支仍不在本轮范围。

Emby 复用原 API 密钥，以 60 秒采样保存个人账户当前会话。仅保留播放业务字段投影，不归档媒体临时 token。没有会话是一次成功的空检查，不生成停止事件；不存在接入前的历史补采。

Navidrome 复用当前源库的只读一致快照，按已有原生 scrobble ID 增量取得历史及后续上报。当前仅有一个账户，其用户名与选择的 Emby 账户匹配；未新增用户、密码或 API key。首次接入取源库全部保留历史，此后每 300 秒检查。未上报的客户端活动与已清理历史无法补齐。

nas-activity-v1 将两种来源分别组织为日阅读对象：条目/会话组、完整时间条目和逐条来源引用。媒体文件总长度与用户观看/收听时长分开，后者保持未知；观察范围不当作连续播放时段。git-pr-v1 提供 PR 的专有字段和正文。旧 display 仅增加这些类型的兼容映射。

M3 有一条活动摘要的前置信息触发 ScannerError，实际源格式不保证严格 YAML。本次 activity-v1 升到 profile 2，只按来源实际使用的标题、描述、应用列表提取；完整正文和既有背景分区保持。后台重建该来源，未运行重复测试。
