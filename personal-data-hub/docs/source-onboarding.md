# 来源接入边界

Hub 当前只承担六类来源：CRM/微信、Skysight、Plaud、Health、AutoAccounting、网络流量。新增来源前先确认原系统缺少哪项同步、持久化或内容处理能力；有独立存储和接口的应用，聚合展示或管理应直接调用其接口，不再复制到 Hub。

当前范围见 [来源清理计划](plans/2026-10-15-source-cleanup.md)。后台轮询和加工仍暂停，不用新增来源或回填命令绕过止血设置。

## 保留来源的实现要求

1. 明确一条记录代表什么、稳定身份如何生成、时间字段的实际含义、更新和删除信号。
2. 原文和附件保持可追溯；不因界面展示重复存整份载荷。现有结构简化在六类来源重设计中逐项实施。
3. 批量或增量读取，水位只在本轮完整成功后推进；失败重跑按稳定身份去重。缓存轮转和时间窗口缺失不判断删除。
4. 推送校验真实外部输入，文件先校验再返回数据库提交确认；设备身份与已有秘密保留。
5. 声明可读结果和质量边界，不把采样观察当作完整活动时长，不将缺失数据补零。
6. 在 `source_policy.SOURCE_KINDS` 声明适配器可写类型。配置、注册和通用入库共同使用该范围；默认查询与后台任务只处理这些适配器对应的来源。

实现完成后集中验证受影响路径，不为可逆配置逐项增加测试，不调用真实模型或重放业务消息充当验收。

## 历史镜像

退出来源的原件、版本、附件、任务和水位保留。默认列表与加工跳过它们，按 ID 的历史读取和备份保留。不能为清空列表而删除正式数据。宿主及容器私有配置先通过 `deployment/cleanup-source-config.py` 生成独立候选；该脚本不会替换在用配置。
