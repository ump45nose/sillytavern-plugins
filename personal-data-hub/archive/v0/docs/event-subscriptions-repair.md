# MCP 事件订阅修复（2026-10-07）

## 原因与修复

聚合迁移时，主服务装配代码强制关闭 `chat_events_enabled`，部署清单也设置了 `CHAT_EVENTS_ENABLED=false`。因此普通 CRM 查询正常，但 MCP Events 的声明、发现、续订及聊天报告生产均停止。网页显示名改为 UserInfo，App ID 和服务 URL 没有改变，改名不是本次根因。

装配代码现在保留显式聊天事件配置，正式清单恢复 `CHAT_EVENTS_ENABLED=true`。未授权的提醒调度和复盘事件仍关闭。保留原 `/data/events`、报告、事件身份、OAuth 盐和密钥，不重建订阅或恢复旧数据快照。旧聊天生产水位为 2026-10-06，恢复后按原规则生成缺失报告；当时没有有效订阅，未投递历史报告。

公共运行时 0.1.6 增加只读 `get_mcp_event_status`。启用 Events 的 CRM、邮件和独立用量 MCP 都提供此工具；按当前 OAuth 主体隔离，返回事件声明、订阅有效期/验证、保留事件数、队列计数和最近 10 次投递。没有回调 URL、签名秘密、订阅筛选参数或业务正文。过期订阅显示无效，不擅自延长有效期。HTTP 2xx 只证明回调接收，不能证明 ChatGPT 的执行或通知显示。
