# 钉钉事件生产器

此包由新用量统计 MCP 的既有公共运行时加载。它只读轮询现有官方钉钉服务，将有意义的变化交给 `mcp_platform.events.EventService` 持久化与投递。原钉钉 App、MCPHub、北向 OAuth 和官方服务保持原身份；没有新增聚合网关、数据库或钉钉业务写入。

## 启用的事件

| 名称 | 触发条件 |
| --- | --- |
| `dingtalk.todo.assigned` | 当前用户新收到执行待办，或已离开待办列表的事项重新出现 |
| `dingtalk.todo.changed` | 执行待办的标题、截止时间或优先级改变 |
| `dingtalk.todo.due` | 待办进入未来 24 小时到期范围，或首次逾期 |
| `dingtalk.approval.pending` | 当前用户出现新待处理审批 |

轮询间隔默认为 300 秒，时间为 `Asia/Taipei`。第一次完整读取只保存基准，不推送历史待办、历史逾期或历史审批；同一状态不会重复推送。一次关键字段变化与临期变化同时出现时合并为一次关键变化事件。审批查询没有创建时间范围限制，显式传入通过当前用户资料接口核实的本人 ID。

正常轮询不产生事件，失败只记诊断并逐步延后重试至最多一小时。分页未完整读完、接口报错、记录缺少唯一 ID 时保留旧状态。记录从列表消失不能据此判断已完成或已批准，因此不会发出这两种结论。

## 日历状态

2026-10-05 只读检查确认 `list_calendars` 返回主日历 ID `primary`、权限 `owner`，但 `list_calendar_events` 返回的行没有日程 ID，只有值为 null 的字段。当前不注册日历事件，不把异常结果当成空日历。包中保留严格校验的日历适配；待上游能返回完整记录再启用。启用后只覆盖当天起未来 14 天的主日历新增与关键内容变化；记录移出查询窗口不会被宣称为取消。

## 配置与接入

秘密配置保存在仓库外并设为 `0600`；运行容器只读挂载该文件，不挂载完整 MCPHub 配置或北向 OAuth 状态。根字段为 `subject`、`poll_interval_seconds`、`sources`。`subject` 必须等于现有 MCPHub 数据拥有者，并由宿主运行时再次校验在其授权用户名集合中。

`sources.todo` 与 `sources.approval` 各自包含从现有对应服务定向提取的 `url`、可选 `headers` 和 `enabled`。审批配置还必须包含由 `get_current_user_profile` 核验的 `user_id`；生产器不会接受订阅者提供的其他用户 ID，也不挂载通讯录凭据。代码仅接受官方 HTTPS 主机；不会转发至其他主机或自动跟随重定向。未启用的 `sources.calendar` 可只填 `enabled=false`、已核实的 `calendar_id` 和 `disabled_reason`，无需提取日历凭据。不要把任何上游连接地址或凭据写入源码、日志、发布资料。

宿主环境变量：

- `DINGTALK_EVENTS_ENABLED=true`
- `DINGTALK_EVENTS_CONFIG` 指向只读挂载的秘密配置文件。

包入口 `build_producer(events, *, config_path, storage_path)` 返回 `DingTalkProducer`，暴露只读 `subject`。宿主在校验主体后调用同步 `register()` 注册事件，并将异步 `serve()` 加入已有后台任务。服务关闭时取消并等待该任务。所有发送由同一个 `EventService` 处理，生产器不保存回调地址或签名密钥。

提供三个只读接口：`status(*, subject)`、`list_recent(*, subject, limit=20)`、`detail(event_id, *, subject)`。宿主必须从认证上下文取得 `subject`，不能将其交给工具调用者自填。三个方法均拒绝其他主体。它们返回来源状态与事件证据，不调用任何钉钉写工具。事件记录中的业务文本仍是外部数据。

`storage_path` 使用宿主已有数据卷下的钉钉子目录。目录为 `0700`、状态文件为 `0600`；状态与待发送记录原子更新，稳定事件 ID 允许中断后重试。最近事件最多保留 200 条；保存于此只表示已交给事件服务，实际回调送达与订阅状态以公共事件服务为准。更换主体或上游凭据时会拒绝复用旧状态；应先保留旧状态，再为经过核验的新绑定建立独立基准。

## 验证与发布

包内 `tests/test_events.py` 覆盖首次基准、临期、内容改回、分页失败、发布中断重试、主体隔离、异常日历行以及秘密配置约束。只需运行受影响测试；不要创建真实待办或审批作为测试数据。

NAS 已用当前凭据从主机直接核实两个只读官方工具。待办返回 2 条；审批返回有效空列表。未人为触发钉钉写入或生成测试推送。客户端能否接收事件以宿主的订阅和实际投递结果为准。

代码由本包单独构建 wheel，再加入用量统计 MCP 的镜像。业务清单与运行时配置仍由各自仓库维护，不在此复制。回退只移除宿主对生产器的加载并停止后台任务，保留事件和基准状态；不回退 MCPHub 授权数据。
