# CRM 独立部署与可读附件

## 范围与决定
- PostgreSQL 唯一数据库；独立 CRM 包和单服务进程只含采集、归档、HTTP/MCP。
- 保留既有人物/交互/来源身份/消息去重与已编辑正文，不重采全量历史，不添加原文/版本/AI 工作流。
- 采集端取得普通可打开附件；服务端不接收微信加密缓存作为成功文件，不管理微信密钥。
- 消息共用一个增量水位，批量回执指示缺失附件；未完成媒体只存定位与重试，不存正文。
- 修复损坏水位、文件漏采、日期一致性；历史数据和后续采集使用同一处理路径。
- 保留原认证与 OAuth 状态；原宿主的其他来源和消费者不被关闭，切换前核对最新运行变更。

## 验收
- [x] PostgreSQL 归档、CRUD、分段/去重/编辑追加/日期/水位回归。
- [x] 媒体首轮不漏、重复不重传、明确文件类型、实际解码/打开。
- [x] 历史附件按原 ID 补齐可读文件，漏建文件附件完成批处理与对账。
- [x] 独立构建无 Hub 依赖；真实 HTTP/MCP 和原认证可用；其他服务保持运行。
- [x] 两台 Mac 后续采集推进；交付真实聊天及实际打开的图片/文件样例。
