# 每日分析数据接口

`get_daily_push_data` 是只读 MCP 工具，HTTP 对应 `GET /api/v1/daily-push`。
默认读取 Asia/Taipei 的今天。只提供 CRM 聊天、健康和财务，移除原始采集 JSON、
设备键、消息源偏移、联系人资料和报告投递统计等不用于分析的字段。

CRM 返回 `crm.contacts`，以 `person_id` 分组，每组包含对象名称和按时间排列的交互。CRM 归档升级后，兼容字段 `messages` 的每项承载一段完整、可编辑的聊天交互，不再是一条源消息；`total_messages` 是该兼容数组的条目数。精确的人物与交互操作使用新的 CRM API / MCP。
消息保留时间、收发方向及正文；源数据提供发言人时一并保留，避免群聊混淆。
同名对象按身份区分。事件中的迟到补采继续保留，时间表示实际业务日期，
并以 `late_arrival=true` 标记。普通按日查询只返回所选日的聊天。

健康以样本日期筛选，步数和活动热量使用区间起始日，睡眠使用会话结束日。
同源重复样本去重，累计值不重复相加，重叠睡眠区间合并。仅返回所选日的步数、
睡眠、静息心率、活动热量和心率统计；不使用昨日指标填充今日。
未采集的指标放在 `missing_metrics`，不补零，不执行诊断或模型分析。

财务以账单发生时间筛选所选业务日，返回全部当日账单以及按币种分别计算的
收入、支出和转账。金额用 Decimal 汇总并以字符串返回。
待确认账单不计入合计；未知账单类型或无效金额计入 `unclassified_count`，
不会被默认为收入。转账单列，不同币种不合并。

## 调用和分页

MCP 当日查询：

```json
{"day":"2026-10-09","timezone":"Asia/Taipei","offset":0,"limit":50}
```

事件查询使用事件的 `report_id`，无需另传日期：

```json
{"report_id":"事件提供的报告编号","offset":0,"limit":50}
```

HTTP 当日查询：`GET /api/v1/daily-push?day=2026-10-09&tz=Asia/Taipei&offset=0&limit=50`，
沿用已有 API / viewer Bearer 鉴权；未鉴权返回 401。HTTP 不开放报告编号查询。

`next_offset` 非空时使用该值继续读取。页面先提供按对象连续排列的聊天，随后提供
账单，因此第一页未必包含账单明细。健康指标和财务汇总仅在第一页返回。
`limit` 范围 1–100，默认 50；偏移计数包含聊天正文分段和账单。
超长聊天按 4000 字符分段，同一 `message_id` 按 `text_offset` 顺序拼接，
`text_total_chars` 用于校验完整性。联系人跨页时按 `person_id` 合并。
实时按日查询可能随采集更新；事件报告固定快照，适合完整分页与重试。

## 事件接入

沿用 `crm.daily_chat.ready`、原 23:00 调度、事件身份、订阅和生产水位。
统一服务的新事件将 `read_tool` 设为 `get_daily_push_data`，报告生成时同时冻结
按对象聊天及该业务日的健康、财务数据。`empty_day` 仅在三类数据均为空时为真。
回调保持小型元数据，数据通过原 OAuth 读取，不向回调塞入全部正文。

升级前报告的原文件保持不变；第一次从新接口读取时，在原事件卷的
`chat-reports/daily-push/` 保存独立投影快照。它使用原报告截止时间筛选样本和账单，
代表首次投影时已归档的数据，不能宣称是原事件产生时的健康或财务快照。
原 `get_chat_event_report` 和 `get_chat_event_message` 继续可供显式全文查询。

接收任务应使用事件指定的新工具并读取全部分页，按对象展示聊天，随后展示当日
健康、财务数据。不要用“读取完成 / 附件已生成”代替实际数据。
服务器变更不会直接重写 ChatGPT 中已保存的任务提示词。
若原任务仍明确要求全文附件，需把原任务改成以下处理要求，保留原事件订阅：

> 收到 crm.daily_chat.ready 后，用事件的 report_id 调用 get_daily_push_data，读取全部分页。
> 将聊天按 person_id 合并分组，并按时间展示对象的聊天记录；超长消息按 message_id 和
> text_offset 完整拼接。展示事件业务日的健康指标、财务汇总及账单。
> 不读取其他个人信息来源，不生成全文原文附件，不以同步计数或读取完成说明代替数据。
> 缺失指标明确写暂无数据；聊天补采保留实际日期。
