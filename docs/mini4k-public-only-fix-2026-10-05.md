# Mini4K 修复与公网下载配置

本次更新共享包 `0.3.1`、公共宿主 `0.1.1` 和 FilmWatchlist `1.4.2`。
网页和 MCP 的 HTTP 协议未变化，现有应用容器无需重建。MoviePilot 镜像及访问入口保持不变。

## 配置边界

配置集中在 MoviePilot 的“公共媒体获取能力”插件：

| 配置 | 当前部署值 | 行为 |
|---|---|---|
| 自动下载仅公网资源 `public_only` | 关闭 | 开启后网页、MCP 和 FilmWatchlist 的自动下载只选公网；失败不退回 PT |
| 公网 BT 下载到 115 `p115_route_enabled` | 开启 | 新安装默认开启；已有明确关闭的配置仍需按使用意图设置 |
| 允许 115 分享转存 `share_115_enabled` | 关闭 | 独立控制分享，不随 BT 路由开启 |

搜索页面继续显示所有站点；通过搜索结果的候选引用手动指定 PT 不受仅公网开关限制。
旧 PT 任务的恢复和片单回写不受影响。公开 BT 仍须确认 `private=false` 和文件覆盖，
不因站点名为公网就跳过核验。

## 两处异常

Mini4K 对《肖申克的救赎》的第三个 TMDB 别名返回正常空结果页，内容包含
`0 个结果` 和 `无任何结果`。旧解析器误报 `PARSE_CHANGED`，因此已有两批候选时
仍把查询标记为异常。现在识别该页面；合法结果被年份或媒体类型过滤也返回空结果，
未知页面结构仍报告异常。真实三别名查询返回 75 个 Mini4K 候选，状态 `OK`。

原 Relay 设备离线；替换受保护凭据后发现新设备没有缓存标签，而旧代码调用了
远端不支持的 `/api/tabs/create`。[Browser Relay 的接口说明](https://github.com/reliefeai/browser-relay#http-api)
仅支持导航已有标签。现在只复用 Mini4K 标签；标签关闭或设备更换后重新选择，
不导航其他网站的标签。设备离线和没有 Mini4K 标签会返回明确原因。
凭据、已登录域名和标签文件权限为 `0600`，不写入本记录或对外回执。
