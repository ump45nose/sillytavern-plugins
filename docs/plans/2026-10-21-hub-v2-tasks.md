# hub-api v2 任务（委派 fn 侧）

Mac 端已按本文的接口形状实现；接口上线前 Mac 显示「hub 尚未提供」，不会报错。沿用 hub-api 现有约定：snake_case JSON、Bearer 设备令牌、不记录 URL / 头 / 正文、写操作只转发一次不重试、单测用假服务、不向生产写测试数据。部署按 `services/hub-api/README.md` 的 NAS 流程。

## 1. 网络套餐手动配置（优先）

Usage Monitor 只给流量计数，没有套餐总量，所以套餐由用户在 App 里配置，hub 存储并据此算出 `pools`。

- `GET /api/v1/net/plans` → `{"items": [Plan]}`
- `PUT /api/v1/net/plans`，body `{"items": [Plan]}`，最多 5 项、`id` 唯一，返回同 GET。存为 `net_plans` 文档（同 subscriptions），成功后失效 `usage` 缓存。
- `Plan`：`id`（1–64）、`name`（1–100）、`total_bytes`（> 0）、`reset_day`（1–28，默认 1）、`expires_on`（日期，可空）。`extra='forbid'`。
- `net` 模块输出 `pools`：每个套餐一项 `{id, name, used_bytes, total_bytes, period_start, period_end, expires_on, source: "manual"}`。
  - `period_start` / `period_end` 由 `reset_day` 推出当前计费周期。
  - `used_bytes` 为该周期内的路由器计数。`reset_day = 1` 时等于 `month_bytes`；其他重置日需要按日的流量，Usage Monitor 若只有自然月合计，就返回 `null`，不要估算，并在交付说明里写明。
  - 多个套餐共用同一个路由器计数，`used_bytes` 相同；这是已知限制，写进 README。
- 现有提醒偏好 `traffic_remaining_percent`、`traffic_expiry_days` 作用到这些 `pools`（检查 attention 的流量规则是否已经读 `pools`）。

## 2. Plaud 录音列表

现在只能按 id 取音频和转录稿。新模块需要按天列出录音：

- `GET /api/v1/recordings?source=plaud&before=YYYY-MM-DD&limit=N`（`limit` 天数，1–30，默认 14；`before` 不含当天，缺省为明天）
- → `{"days": [Day], "next_before": "YYYY-MM-DD" | null}`，按日期倒序，只含有录音的日子。
- `Day`：`{date, recordings: [{id, title, start_at, duration_seconds}], has_transcript, people: [name]}`
  - `id` 沿用 `plaud:<date>:<audio_id>`，现有 `/audio`、`/transcript` 接口不变（转录稿是整天的 Markdown）。
  - `people` 复用 crm 模块里录音与交流的时间重叠匹配；匹配不到给空数组。
  - `has_transcript` 只看 `transcript.md` 是否存在，不读正文。
- 每天的 archive 详情并发不超过 4，结果缓存 60 秒。

## 3. Token 模块补字段（成本保持美元）

`GET /api/v1/modules/token?range=day|week|month` 补以下字段；Token Monitor 的 stats 没有的就返回 `null` 并在交付说明里列出，不要估算：

- `history`：全部时间的每日 `[{date, total, cost}]`。先确认 `historyPreview.daily` 是否覆盖全部历史；不是的话找 Token Monitor 的完整历史接口。
- `models`：所选区间 `[{id, name, provider, total, cost}]`，按 `total` 倒序。
- `tools`、`devices`：改为跟随所选区间（现在只有当天）。
- `sessions`：所选区间用量最高的 20 个会话 `[{id, title, tool, model, device, total, cost, updated_at}]`。用户已同意显示会话标题；仍不保留会话内容、项目路径、账号和凭据字段。README 里「Retain no session…」一句相应改成「只保留会话标题与用量」。

### 3.1 验收反馈（2026-10-22，Mac 端已按下列字段适配）

- `sessions` 目前只有 `range=day` 返回，且 20 条都没有 `title`。请补 `title`（Token Monitor 的会话名/首条提示摘要，截断到 80 字），并让 `week`、`month` 也返回。
- `limits[]` 加可选 `account`：同一工具多账号时用来区分（例如两条 `cursor`，一条 Enterprise、一条 Free）。用 Token Monitor 里该账号的显示名或邮箱，没有就省略；Mac 端在没有 `account` 时退回用 `plan` 区分。这是额度归属标签，不是凭据，不受上面「不保留账号字段」限制。

## 4. Memos 增删改查

只操作当前用户自己的 Memo；id 校验格式；写操作后失效 `memos` 缓存。

- `GET /api/v1/memos?page_size=20&page_token=&tag=&q=` → `{"items": [Memo], "next_page_token": str | null}`。`tag`、`q` 用 Memos 官方 filter，不在 hub 扫全文。
- `GET /api/v1/memos/{id}` → `Memo`
- `POST /api/v1/memos`（已有），返回值补成完整 `Memo`。
- `PATCH /api/v1/memos/{id}`，body `{content?, visibility?, pinned?}` → `Memo`
- `DELETE /api/v1/memos/{id}` → 204。实现为归档（Memos `state = ARCHIVED`，可在 Memos 里恢复），不做永久删除。
- `Memo`：`{id, created_at, updated_at, content, tags, visibility, pinned, url, attachments: [{name, filename, type}]}`。附件图片如需显示，另加只读代理 `GET /api/v1/memos/{id}/attachments/{name}`（只接受该 Memo 自己的附件）。

## 5. 布局文档（无需改动，告知安卓）

`/api/v1/layout` 不校验结构，Mac 会写入三种新内容：

- 页面 `kind: "review"`（复盘内置页，id `review`，Mac 会自动补进旧布局）；
- 模块 `module: "plaud"`（录音，默认放在生活页）；
- 模块项可选字段 `height: "medium" | "tall"`（缺省为自动）。

安卓读到不认识的页面类型或模块时，应保留原样、不要删掉后写回；Mac 这边遇到不认识的值会把整份文档视为不可读并且不覆盖，安卓最好同样处理。安卓不展示复盘页和录音模块也可以，但写回时要原样带上。
