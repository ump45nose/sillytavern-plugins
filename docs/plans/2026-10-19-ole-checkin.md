# Olé 自动签到

## 范围与决定

- 仅在 `codex/benefits-ole-20261019` 工作区维护 Olé 平台、测试和本计划，公共运行器、YYB 客户端及调度由其他任务维护。
- 提供 Python 标准入口与 Node.js 一次性业务适配器，复用 `common.runner`、账号锁、私有运行目录和 JSON schema v1。
- 参考 smallfawn/QLScriptPublic 的 `wxapp/olecs.js` 当前协议，独立实现必要请求和结果核实，不复制完整脚本及其框架。
- `OLE_CONFIG` 指向仓库外、归当前身份所有的私有 JSON（0600 或本身份所属组的 0640/0660）；微信取码采用已集成的 `getCode({url,token,account}, appid)`。缓存的是 Olé 商家 session/openid，不是微信 code。
- 门店可选：明确配置、商家登录/状态响应中的 `shop_code`，或本人提供位置对应的查询；没有时按固定参考发送空 `enter_shop_code`。不提供作者定位，不把位置或门店设为签到前提。
- 每日签到只提交一次；先持久化 intent，再发送 POST，随后 GET 读回。提交后结果不明跨进程保留 pending，当日仅查询恢复。
- 已签到和积分查询分别报告。余额前后差仅表示本次观测窗口变化，不能代替签到发奖数。

## 验收

- 未加 `--execute` 不读取凭据、不访问平台；缺配置时结构化失败，不依赖尚未集成的 YYB 模块。
- 验证缓存会话失效后只刷新登录一次；网络/接口故障不误作会话失效。
- 已签到不提交；未知签到状态或明确未注册不提交；缺门店使用空值，并以 GET 独立读回确认。
- 模拟提交返回/连接中断后成功读回、读回失败及跨次 pending 恢复，证明不重签、不伪造积分。
- 验证私有文件权限/原子写入、固定商家源、响应体上限和拒绝重定向。
- 真实账号验收分别核对扫码、商家登录、签到与积分读回；长期自然过期续登单列，不用模拟替代真实结果。
