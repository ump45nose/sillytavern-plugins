# EH 收藏扫描超时与漏项

## 范围与证据

- 仅修改 Favsync 的 EH 收藏列表扫描、gallery-dl 子进程入口与对应验证；保留下载、Cookie、数据库基线及现有文件。
- 生产日志：2026-10-18 04:01:47 至 05:01:47 扫描超时，后续四轮完成但均为零条。
- 固定版本 `ExhentaiFavoriteExtractor` 输出 `Message.Queue`（6），现适配器只接受 2/3；真实收藏页面包含图库链接。
- 上游分页在响应缺少结束/下一页标记时直接增加 page，异常页面会不断请求直到全局超时。历史响应未保留，无法证明该缺口就是当时超时的原因。

## 决定

- 复用固定版本 gallery-dl 的认证、代理、请求节奏、有限重试和 DataJob；仅用本地收藏提取器校验分页，扫描不展开图库图片。
- 当前收藏分页必须有下一页/结束标记或明确的空结果。拒绝未知响应、非收藏下一页和重复游标，错误时不提交部分结果。
- 读取 Queue 事件，按图库 ID 去重。沿用现有基线，不重建、不手工清除历史错误。
- 使用聚合仓库 `.worktree/eh-favorites-timeout-20261019`，主工作区有他人修改，不自动合并。
