## 1. 范围

做：

## 2. 硬性约束

- **不打印秘密**：Memos 令牌、Telegram 凭据、新增的服务令牌不进日志、命令输出、提交和响应体。看 `.env` 只看变量名。
- **不产生生产测试数据**：日报 / 周报 / 阶段结案 / 目标评论 / 新周期在生产上只用 `dry_run` 验证。真实确认由 玮康 在 App 里完成，作为最终验收。
- **不影响现有流程**：今晚 21:30 的日报定时任务、Telegram 回复确认必须照常可用。改 Skill 与 cron prompt 时保留任务 ID、schedule、投递 topic、执行历史与暂停状态（见 personal-review README）。
- **运行身份**：HTTP 服务以 `hermes` 用户运行，复用 `/vol2/1000/Docker/personal-review` 的配置、数据库和 `.env`，参照 `plaud-archive.service` 的 systemd 方式。只监听 `192.168.31.201`，端口选一个空闲的（当前 18102、18103、18186、18187、18190 已占用），Bearer 令牌只放在 hub-api 的 env 里。
- **SQLite 并发**：HTTP 服务和 CLI 共用 `state/review.db`。写操作复用现有 service 方法（它们已经带幂等键），不要另写 SQL；如未开 WAL / busy_timeout，先评估再加。
- **提交边界**：personal-review 改动按聚合仓库 `AGENTS.md` 在其 worktree 里提交；hub-api 只改 `services/hub-api/`、`docs/`，不改 `apps/macos/`。推送前先 `git pull --rebase`。

## 3. personal-review HTTP

新增 `reviewctl serve [--host --port]`（或独立入口），JSON 字段 snake_case，时间带 `+08:00`。错误格式沿用 hub 约定 `{"error": {"code", "message"}}`；**规则校验失败返回 422，`message` 用 service 抛出的中文原文**（如「一句话总结不能超过 45 个字符」），并尽量附 `field`（字段名，如 `一句话总结今天`、`瞬间`；整体性错误为 null）。会话过期返回 409 `code=expired`。

| 方法 | 路径 | 对应 CLI / service |
| --- | --- | --- |
| GET | `/v1/reviews?kind=daily\|weekly&limit=14` | 读 `review_sessions` |
| GET | `/v1/reviews/{id}` | 同上 + 材料 + 投递原文 |
| POST | `/v1/reviews/{id}/preview` | `finalize(..., dry_run=True)` |
| POST | `/v1/reviews/{id}/finalize` | `finalize(...)` + App 归档通知（§5） |
| GET | `/v1/stage` | `mainlines`、`stage_cycles`、`stage_goals` + 目标最近一条评论 |
| POST | `/v1/stage/goals/{id}/comments` | `comment_goal(id, text, dry_run)` |
| POST | `/v1/stage/cycles/{id}/close` | `close_cycle(id, text, outcomes, dry_run)` |
| POST | `/v1/stage/cycles` | `create_cycle(starts_at)`，仅当没有 active / awaiting_close 周期 |
| POST | `/v1/stage/cycles/{id}/goals` | `add_goal` + `publish_goal`；`dry_run` 只校验不入库 |

字段见 §4 的 hub 接口，personal-review 与 hub 两层用同一形状，hub 只做认证、超时、转发和模块组装。

## 4. hub-api 接口约定（Mac / 安卓共用）

### 4.1 `goals` 模块（`/api/v1/modules` 里）

来源 `review`（TTL 60s）。personal-review 不可达时按阶段 3 规则返回 `stale` / `error`。

```json
{
  "mainline": {
    "domain": "总主线",
    "direction": "…", "purpose": "…", "meaning": "…", "status": "…", "recent_change": "…",
    "memo_name": "memos/…", "updated_at": "2026-09-14T16:40:00+08:00"
  },
  "cycle": {
    "id": "2026-S4A94", "index": 1, "status": "active",
    "starts_at": "2026-09-14T16:38:02+08:00", "ends_at": "2026-10-26T16:38:02+08:00",
    "day": 38, "total": 42, "preclose_at": "2026-10-25T16:38:02+08:00"
  },
  "goals": [
    {
      "id": "2026-S4A94-1a2b3c", "domain": "事业", "status": "active",
      "goal": "…", "progress": "…", "deadline": "2026-10-26",
      "success_criteria": "…", "stop_signal": "…", "memo_name": "memos/…",
      "latest_comment": { "text": "…", "created_at": "…" }
    }
  ],
  "reviews": {
    "daily": { "id": "daily:2026-10-21", "label": "2026-10-21", "status": "open", "prepared_at": "…", "expires_at": "…", "memo_name": null },
    "weekly": { "id": "weekly:2026-W42", "label": "2026-W42", "status": "open", "prepared_at": "…", "expires_at": "…", "memo_name": null },
    "next_daily_at": "2026-10-21T21:30:00+08:00",
    "next_weekly_at": "2026-10-25T21:50:00+08:00"
  },
  "close": { "status": "none", "cycle_id": "2026-S4A94", "template": null }
}
```

- `mainline` 没有时为 null；`cycle` 没有 active / awaiting_close 周期时为 null（此时 `goals` 为空数组，`close.status` 为 `closed` 或 `none`）。
- `cycle.index` 为按 `starts_at` 排序的序号（从 1 起）；`day` 按本地日计算，第一天为 1，超过 `total` 时取 `total`。
- `goals` 只列当前周期的目标；`progress` 是用户写的文本，不是数字，不要换算成百分比。
- `latest_comment` 取目标 Memo 的最近一条评论（经 Memos 读；失败时为 null，模块 `partial`）。
- `reviews.daily` / `weekly` 取**最近一个会话**：`status` 为 `open`（未确认且未过期）、`finalized`、`expired`（未确认但 `expires_at` 已过）。还没有会话时为 null。
- `close.status`：`none`（未到预备期）、`preclose`（已过 `preclose_at`，模板可用）、`awaiting_close`（已过结案日被冻结）、`closed`（最近周期已结案且尚未开新周期）。`template` 在 `preclose` / `awaiting_close` 时给出（`prepare_close` 冻结的模板；没有冻结记录时按同一格式现算，不写库）。

### 4.2 日报 / 周报

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/review/sessions?kind=daily\|weekly&limit=14` | `{items: [会话摘要]}`，按 `id` 倒序；摘要同 §4.1 `reviews.daily` |
| GET | `/api/v1/review/sessions/{id}` | 会话详情，见下 |
| POST | `/api/v1/review/sessions/{id}/preview` | body `{content}` → 200 `{content}`（补好健康、财务、去掉空字段后的终稿）或 422 |
| POST | `/api/v1/review/sessions/{id}/finalize` | body `{content}` → 200 `{status: "finalized", memo_name, already: false}`；会话之前已确认时返回 `already: true` 和原 `memo_name`，不写新内容 |

会话详情：

```json
{
  "id": "daily:2026-10-21", "kind": "daily", "label": "2026-10-21",
  "status": "open", "prepared_at": "…", "expires_at": "…", "memo_name": null,
  "material": { "sections": [{ "title": "Skysight", "blocks": ["…markdown…"] }], "template": "#日报 2026-10-21\n一句话总结今天：\n…" },
  "delivered": { "text": "…Telegram 实际发出的 markdown…", "delivered_at": "…" },
  "final_content": null,
  "rules": {
    "fields": ["情绪", "健康", "财务", "留痕", "未解", "明天唯一重点", "瞬间"],
    "auto_fields": ["健康", "财务"],
    "summary_max_chars": 45, "summary_max_list_separators": 1, "max_unresolved": 2,
    "moment_min_chars": 6, "emotion_words": ["愉快", "…"]
  }
}
```

- `material` 用 `material_json` 的 `sections` 与 `template`，**不返回 `source_status` 等内部字段**。周报同形，`rules.fields` 取 `weekly.fields`，`auto_fields` 为 `["身体"]` 之类由 CLI 补的字段（没有则空数组），日报专属的数值规则省略。
- `delivered`：当天日报 / 当周周报对应 Hermes 定时任务的输出文件（`REVIEW_JOBS_FILE` 同目录 `output/<job_id>/*.md` 里 `## Response` 之后的部分，参照 `personal-review-daily-ack.py` 的匹配方式）。找不到或投递失败时为 null，不报错。只返回 Response 正文，不返回 prompt、工具调用或日志。
- `final_content`：已确认时为终稿正文；否则 null。
- `finalize` 记录确认来源（`app`），供 §5 通知与审计；正文原样交给 `finalize`，不做轻编辑。

### 4.3 主线与阶段

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/stage/goals/{id}/comments` | body `{text, dry_run}` → `{status: "dry-run"\|"commented", content?, comment_name?}` |
| POST | `/api/v1/stage/cycles/{id}/close` | body `{text, outcomes: {goal_id: "成功"\|"失败"\|"停止"}, dry_run}` → `{status: "dry-run", content}` 或 `{status: "closed", memo_name}` |
| POST | `/api/v1/stage/cycles` | body `{starts_at?}`（默认现在）→ `{cycle_id}`；已有 active / awaiting_close 周期时 409 |
| POST | `/api/v1/stage/cycles/{id}/goals` | body `{domain, goal, progress, deadline, success_criteria, stop_signal, dry_run}` → `{goal_id, memo_name}`；超过 5 个、未知领域、字段为空时 422 |

- `close` 的 `text` 是用户原文，原样交给 `close_cycle`（不润色），`outcomes` 必须覆盖周期内全部目标。
- 新增目标 = `add_goal` 后立即 `publish_goal`；`publish_goal` 失败时返回 502 并保留已建索引，重试同一请求时不重复建目标（用请求里的 `idempotency_key` 或按 `cycle_id+domain+goal` 去重，二选一并写进文档）。
- 写操作成功后立即让 `goals` 模块缓存失效。

### 4.4 需要注意规则

加入 `/api/v1/modules` 的 attention，`module` 为 `goals`，ID 稳定、可 `dismiss` / `snooze`：

| ID | 条件 | 标题 | 副标题 | severity |
| --- | --- | --- | --- | --- |
| `review:daily:{day}` | 最近日报会话 `open` | 日报待确认 | 「{N} 小时后过期」（不足 1 小时写分钟） | `warn` |
| `review:weekly:{label}` | 最近周报会话 `open` | 周报待确认 | 同上 | `warn` |
| `stage:close:{cycle_id}` | `close.status` 为 `preclose` 或 `awaiting_close` | 阶段待结案 | `preclose`：「{M/D} 结案」；`awaiting_close`：「已过结案日，目标已冻结」 | `warn` / `critical` |
