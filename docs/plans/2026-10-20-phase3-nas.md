## 4. hub-api 设计

### 4.1 结构

```text
services/hub-api/
  pyproject.toml            uv 管理；FastAPI、httpx、pydantic-settings、authlib（或等价 OIDC 库）
  src/hub_api/
    app.py                  路由装配、错误处理、请求日志（不含 Authorization）
    settings.py             全部配置来自环境变量；HUB_* 前缀
    auth.py                 OIDC 回调、设备令牌签发 / 校验 / 吊销
    store.py                SQLite：devices、layout、preferences、subscriptions、attention_state、cache
    sources/                每个来源一个适配器：fetch() 返回规范化数据，带超时
    modules/                每个模块组装 §5.4 的 data
    attention.py            §5.6 规则
  tests/                    pytest；每个来源有假服务；不访问真实来源
  Dockerfile
  deploy/compose.yaml       NAS 栈模板（不含秘密）
  deploy/hub.env.example    变量名清单
  README.md
```

### 4.2 来源隔离与缓存

- 每个来源适配器独立超时（默认 5s；GitHub 实测完整通知详情链路约 9.5s，单独使用可配置的 15s），并发拉取；一个来源失败只让依赖它的模块变为 `partial` / `stale` / `error`，批量接口仍返回 200。
- 内存或 SQLite 短期缓存，每个来源单独设 TTL：健康、账单、交流 60s；媒体、Token、网络 30s；GitHub 120s。来源失败时，在 24 小时内返回上次成功的数据，并标记 `stale`。缓存可以随时删除。
- `GET /api/v1/status` 汇总每个来源的最近成功时间、最近错误（只保留错误类型和 HTTP 状态码，不带响应体）和延迟。

### 4.3 认证

- **设备登录（OIDC + 回环 PKCE）**：
  1. 客户端生成 `code_verifier`，打开浏览器访问 `GET /auth/start?device_name=MacPro&redirect_uri=http://127.0.0.1:{port}/callback&code_challenge=...&state=...`。安卓的 `redirect_uri` 用 `personalhub://auth`。
  2. hub-api 作为 Authelia 的 OIDC confidential client 跳转到 Authelia 登录，在 `/auth/callback` 校验 id_token。只允许配置中的精确 `sub`（`HUB_ALLOWED_SUBJECTS` JSON 数组，不按用户名或邮箱放行）。
  3. 校验通过后，hub-api 重定向到客户端的 `redirect_uri?code=一次性码&state=...`。一次性码 60 秒内有效，只能用一次（错误 verifier 也会消费）；服务端到 Authelia 另用一组 S256 PKCE，浏览器状态同时绑定 Secure/HttpOnly Cookie。
  4. 客户端调用 `POST /auth/token {code, code_verifier}`，得到 `{device_id, token}`。
- `redirect_uri` 只接受 `http://127.0.0.1:{任意端口}/callback` 和 `personalhub://auth`。
- 设备令牌是 32 字节随机数（base64url），库里只存 SHA-256。请求头 `Authorization: Bearer <token>`。`last_seen` 按分钟级别更新。
- `GET /api/v1/devices` 列出设备，`DELETE /api/v1/devices/{id}` 吊销。
- NPM 上 `hub-home` 不挂 Authelia forward-auth：API 用 Bearer，只有登录流程经过 Authelia。`/auth/*` 做速率限制。
- 开发和测试用 `HUB_DEV_TOKEN`：只有设置了才启用，生产不设；OIDC 与开发令牌同时配置时拒绝启动。

## 5. 接口约定（Mac / 安卓共用）

### 5.1 通用

- 基址：`https://hub-home.172906573.xyz`，局域网 `http://192.168.31.201:{port}`。
- JSON 字段用 snake_case。时间用带时区偏移的 ISO 8601（`Asia/Shanghai`）；日期用 `YYYY-MM-DD`，按本地日。
- 单位：账单/订阅金额用人民币元（数字，两位小数）；Token 的 `cost`、`today.cost` 沿用 Token Monitor 的估算美元（与 Mac 现有 `$` 展示一致，不作隐式汇率换算）；Token 用原始个数（整数）；流量用字节（整数）；时长用分钟或秒，字段名带单位。
- 不在接口里分配颜色。`tone`、配色和文案格式都由客户端决定。
- 错误响应：`{"error": {"code": "unauthorized|not_found|bad_request|conflict|upstream", "message": "..."}}`，`message` 不含来源细节。

### 5.2 模块信封

```json
{
  "module": "health",
  "status": "ok",
  "updated_at": "2026-10-20T17:58:00+08:00",
  "sources": [{ "id": "records", "status": "ok", "updated_at": "2026-10-20T17:57:41+08:00" }],
  "data": {}
}
```

`status` 取值：

- `ok`
- `partial`：部分来源失败，`data` 里对应字段为 null。
- `stale`：使用缓存。
- `error`：没有可用数据，`data` 为 null。
- `unconfigured`：缺少凭据。

### 5.5 布局与偏好

- `GET /api/v1/layout` → `{"version": 3, "updated_at": "...", "document": {...}}`。`document` 原样存储 Mac 的 `LayoutDocument` JSON（`version`、`pages[{id, title, subtitle, kind, items[{module, size, span?}]}]`），服务端只校验是合法 JSON 且不超过 64KB。还没有布局时返回 404。
- `PUT /api/v1/layout`：body 为 `{"document": {...}}`，请求头 `If-Match: <version>`（首次写入用 `If-Match: 0`）。版本不一致返回 409，响应为 `{"error":{"code":"conflict","message":"conflict"},"current":{"version":...,"updated_at":...,"document":...}}`；还没有布局时 `current=null`。
- `GET / PUT /api/v1/preferences`：同样带 version，PUT 使用 `{document: {...}}`，省略字段补默认值，未知字段拒绝。未保存时 GET 返回默认值、version=0、updated_at=null。字段如下（括号内为默认值）：
  - 额度阈值 `token_limit_percent`（80）
  - 流量阈值 `traffic_remaining_percent`（10）、`traffic_expiry_days`（3）
  - GitHub 阈值 `git_reply_hours`（24）、`pr_blocked_days`（3）
  - 其他规则阈值 `subs_renew_days`（7）、`stale_contact_days`（30）
  - 周期 `cycle_start`（null）
  - 预算 `month_budget`（null）
  - 健康目标 `step_goal`（8600）、`kcal_goal`（520）、`exercise_goal`（45）

### 5.6 需要注意规则

| rule | 条件 |
| --- | --- |
| `token_limit` | 任一额度窗口 ≥ `token_limit_percent` |
| `traffic_low` | 订阅剩余 < `traffic_remaining_percent`，或 `traffic_expiry_days` 天内到期 |
| `git_waiting` | 等回复超过 `git_reply_hours` 小时 |
| `pr_blocked` | PR 阻塞超过 `pr_blocked_days` 天 |
| `subs_renew` | `subs_renew_days` 天内续费 |
| `stale_contact` | 有联系人超过 `stale_contact_days` 天未联系；只出一条汇总 |
| `source_down` | 某来源连续失败超过 30 分钟，或数据超过 6 小时未更新 |

计算时机：每次请求 attention 时用缓存数据计算，不额外定时拉取。
