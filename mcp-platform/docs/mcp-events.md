# MCP Events 接入与部署

公共运行时从 0.1.4 起可显式加载 EventService。没有加载事件服务的应用保持原接口与生命周期；认证、授权、OAuth 密钥和持久化存储仍使用原配置。

## 协议与权限

事件发现和订阅通过同一已认证的 `/mcp` 入口，提供 MCP 2 的 `server/discover`、`events/list`、`events/subscribe`、`events/unsubscribe`，协议版本为 `2026-07-28`。旧版 MCP 工具客户端继续由现有 SDK 处理。

生产事件必须绑定明确的授权主体；请求体不能指定或覆盖该身份。ChatGPT 提供回调地址和签名秘密，事件服务验证回调并使用 Standard Webhooks 签名投递。回调需要可验证的 HTTPS；禁止本机、私网及跳转，DNS 校验结果固定到实际连接。明确配置的可信出口代理仅用于 CONNECT，不改变目标检查或 TLS 验证。

订阅、待投递事件及重试状态使用原加密存储机制，并持久化在业务数据卷。稳定事件 ID、持久队列和消费者游标共同防止重复与丢失；收到 2xx 只代表回调接收，不代表 agent 已完成执行。

## 本次业务接入

- CRM：每天 Asia/Taipei 23:00 固化当天零点至截止时的聊天原文快照；通过报告 ID 分页读取，晚到记录在后续报告补充，未采集到的原文明确标识缺失。
- 邮件：启动时建立接收基线，只检查之后的新邮件；每个授权账号独立保存 UIDVALIDITY 和 UID 游标。重要性筛选只读信封及元数据，不标已读、不发送邮件。
- 钉钉：待办新增、重要属性变化、到期提醒及新待审批事项。初始读数作为基线，不回放历史；读取失败不按空列表处理。日历因为上游缺少事件 ID 暂停启用。
- 用量统计：Token Monitor 与 ShellCrash 每天合为一份日报；明确当天范围、截止时间、离线状态和缺失数据。只读绑定数据目录，秘密配置单独以 0600 文件只读挂载。

## 部署与接入

清单的 `bind_mounts` 只接受绝对路径、非根路径且禁止 `..`；绑定挂载固定为只读。原命名持久卷继续保留。

先完成生产入口、认证、发现和原业务工具验证，再在原生 ChatGPT 自定义 MCP 服务器中刷新发现。新增“用量统计”使用单独域名和 OAuth 客户端，复用现有 Tunnel 和 Authelia。原 CRM、邮件与钉钉 App 身份继续沿用。

只有 ChatGPT 列出事件源且真实订阅创建成功后，才能将用户推送标记为启用。不能以内部定时采集、事件写入队列或普通 SSE 通知替代订阅成功，也不能替换为轮询自动化。
