## 优先发现

### R1 · P1：平台故障隔离在下载阶段失效

`engine.py:258–284` 仅处理 `SyncError` 和 `OSError`，`drain()` 的 bundle 分支也只有这两类边界。`WallabagAdapter._validate_epub()` 在 ZIP 缺少 `mimetype` 时会抛出未转换的 `KeyError`（`adapters_pixiv_wallabag.py:394`）。异常穿过 `_cycle()`，后面的平台本轮不执行，常驻进程随后退出。

离线复现：构造缺少 mimetype 的 ZIP 得到 `KeyError`；让 Wallabag bundle 抛同样异常，后续片单适配器的调用次数为 0。当前样本没有触发，不应把它描述为正在发生的线上故障。

建议先统一适配器错误转换，再在每个来源的执行边界保存该来源失败并继续下一来源。不要只在最外层吞异常，也不要把异常任务标记完成。鉴权、限流等账号级错误应停止该账号后续请求；当前 bundle 仅对小红书执行此策略，其他 bundle 平台仍会继续遍历同一账号的队列。

### R2 · P1：媒体校验为读取 16 字节而加载整个文件

`adapters_ext.py:30–33` 使用 `path.read_bytes()[:16]`，被小红书、EH、Pixiv 共用。文件越大，瞬时内存需求越大；附件不限大小时可能拖垮整个同步进程。当前闲置内存低不代表下载大视频时没有这个问题。

直接改为打开文件读取固定长度。将该无平台依赖的函数放到公共媒体校验模块，解除 Pixiv/Wallabag 模块对 EH/小红书模块的反向依赖；无需引入新的校验框架。

### R3 · P2：小红书“已发现”过滤阻止失败任务更新访问令牌

`adapters_ext.py:186–190` 只返回未见过的 ID；`store.py:233–246` 的 locator 更新必须先收到扫描记录。因此某条笔记第一次发现后下载失败，下一轮即使列表给出新 xsec_token，也会在适配器里被过滤，待重试队列仍使用旧 URL。

离线复现：持久化一个 `media_url_expired` 任务，再返回带新令牌的同 ID，扫描返回 0 条，队列仍保留旧令牌。

“新增入队”和“未完成任务刷新 locator”应分开。已完成任务可忽略；未完成任务要接收新 locator，并让缓存详情与其一致失效，保留原来的命名和发现时间。

### R4 · P2：全局锁覆盖常驻进程的 8 小时睡眠

`cli.py:110` 在进入 `engine.run()` 前持有 `worker.lock`，`engine.py:419/423` 的睡眠也在锁内。常驻进程即使闲置，`sync-once` 和 Telegram 登录仍会得到 `worker_already_running`，用户只能停掉所有平台才能操作一个来源。

把锁缩到实际执行区间。第一步保持单进程串行执行，避免引入并发改造；后续如需来源独立运行，共享登录会话的来源使用同一账号锁。不能简单给每个来源一把独立锁后并行访问同一个 Telegram/XHS 会话。

### R5 · P2：平台配置和数据库启动逻辑耦合到片单 API、状态读取

`cli.py:47` 对任何命令都加载并校验全部平台配置；即使平台关闭也会校验。离线复现：Wallabag 已关闭但 `per_page=0`，配置加载仍失败，片单 API 无法启动。

`film_api.py:19` 和 `cli.py:58` 都实例化完整 `Store`；`store.py:70–84` 在每次打开连接时执行迁移检查、Wallabag 历史状态修补和 Markdown 启用时间初始化。因此读状态、Cookie 同步、启动片单 API 都携带下载平台的写入副作用。

保留同一个 SQLite，但分开“打开连接”“版本化迁移”“平台仓储方法”。迁移由应用启动显式执行一次；API 只验证公共配置和片单配置，停用来源的私有配置延后校验。无需增加数据库服务。

### R6 · P2：片单中有两个可直接复现的小缺陷

- `film_api.py:141` 调用 `date.fromisoformat`，文件只导入了 `datetime`。运行容器也缺少 `date` 符号。手动 POST 携带字符串 release_date 会抛 `NameError`，无法正常写入或返回约定的错误响应。该问题位于已有未提交的手动片单代码中。
- `film_watchlist.py:85` 对截取后的空文本直接取 `splitlines()[0]`。`country_info('法国电影《示例》', '上映日期：')` 离线复现 `IndexError`；任何单条简介出现这种输入，都可能让整次片单入库失败，而不是回退到标题国家或 null。

先修边界处理和缺失导入，保持现有 country、上映时间、downloaded 的语义。

### R7 · P2：完成状态和日报没有表达受限扫描、附件不完整

小红书达到新条目/页数预算后仍返回 `(records, None)`（`adapters_ext.py:167–204`）；`Store.ingest()` 一律写 `complete`（`store.py:253`）。收藏与点赞共享预算，而收藏先执行：若收藏用满额度，点赞可以没有发出列表请求也被记为完成。这是受限增量，不能被解释为完整分页。

此外 `Store.status()` 已给出 EPUB 附件状态，但 `scripts/hermes_favsync_daily_summary.py:77–105` 未读取它。目前的 2 个图片不完整 EPUB 不会进入日报提示。

适配器返回明确的结束原因（列表结束、已见边界、预算耗尽），调度器据此记录扫描状态。日报保留简短成功/失败，同时补“正文已保存，图片不完整 N 条”即可，不必扩成复杂监控平台。
