# 脚本执行与验收

- Agent 负责分析、修改代码和检查证据；签到、积分提交、领取及其恢复统一由 `platforms/<platform>/run.py` 或正式 Hermes 包装执行。只读诊断与正式业务结果分开记录，诊断入口不代替正式脚本完成业务。
- 奖励判断、网页交互和验证均由确定性脚本完成，不接入语言或视觉模型求解器。必须解题的站点验证明确报告需要人工处理，不由 Agent 解题或代领后再让脚本读取成功状态。
- 修复保留账号身份、原动作 journal 与历史回执。正式入口自然生成新的 run/result/delivery；不直接写成功回执，不清除不确定 intent 以授权重放。
- 先验证缺陷对应的代码路径，再使用正式入口验证；已完成动作的读回只证明查询与去重，不证明首次提交或未来长期稳定。没有当日可安全执行的首次动作时，在验收中明确缺口。
